# Groundhog Vault UI: Before and After

## Outcome

The selected Proposal 1 + Proposal 2 hybrid is now a production interface rather than a staged mock. It preserves the cinematic session boundary while making the evidence chain and field-use case inspectable.

| Area | Before polish | After polish |
|---|---|---|
| Experiment chronology | One backend request computed both lives, then the UI revealed them in stages | Run creation, Life 1, and Life 2 are separate requests; the network chronology matches the presentation |
| Memory claim | Sibyl persistence was real but easy to mistake for a visual effect | Fresh runtime IDs, database identity, incident, promoted policy, cited decision, and Memory Lift form a visible causal chain |
| Accessibility | Skip target could remain hidden; overlays left focus behind them; announcements were broad | Skip enters Arena and focuses its heading; busy content becomes inert; error focus is trapped/restored; one concise live region announces outcomes |
| Mobile | Dense production mapping had no scroll cue | A visible comparison cue and horizontally scrollable production table preserve all three columns |
| Motion | Reset timing was fixed | Reduced-motion users receive near-instant state changes and non-animated progress |
| Typography | Literal sizes and a specificity override weakened the system | Named tokens govern the active hierarchy and no `!important` override remains |
| Product story | Prototype and production behavior blurred together | The arena is labeled simulation-only; the Field Map states the constrained production path and human-approval boundary |

## Judge path

1. Enter the controlled loop and run Life 1.
2. Observe identical 30% allocations and identical losses.
3. Inspect the fresh-session boundary and persisted Sibyl database.
4. Run Life 2 against the renamed opportunity with the same risk signature.
5. Observe Groundhog cite the promoted policy and cap exposure at 5%, while Amnesiac repeats 30%.
6. Open Evidence to trace incident → policy → fresh decision, then Field Map to see the real treasury-guardian use case.

## Verification

- Four deterministic tests cover full and incremental execution, causal memory dependence, and recall through a newly constructed Sibyl client.
- Python bytecode compilation and JavaScript syntax validation pass.
- The UI rule audit reports zero violations.
- Desktop, narrow-screen, reduced-motion, empty, loading, reset, error, and success states were reviewed.
